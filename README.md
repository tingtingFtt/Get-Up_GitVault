# Run and deploy your AI Studio app

This contains everything you need to run your app locally.

View your app in AI Studio: https://ai.studio/apps/b4462d66-9b70-4b20-a34a-f5bf543cf034

## Run Locally

**Prerequisites:**  Node.js


1. Install dependencies:
   `npm install`
2. Set the `GEMINI_API_KEY` in [.env.local](.env.local) to your Gemini API key
3. Run the app:
   `npm run dev`

## 完整项目同步与版本缓存

使用 Node.js 22，执行 `npm ci` 安装锁定依赖。`npm run lint` 检查类型，`npm test` 运行同步、存储和页面操作回归测试。

- 首次获取会固定源提交 SHA，校验完整文件清单和每个 Git blob；优先下载压缩包，失败时切换到 GitHub 文件接口。请求有超时，操作可取消。
- 浏览器会暂存已校验的下载片段；重试同一提交时复用已完成的文件。目录很多时完整遍历截断的 Git tree；目录导出不再截取前 100 个文件。
- 缓存按项目、提交和文件内容保存。旧版未绑定提交的缓存只有与快照校验一致时才迁移；保存失败会明确报错，不会把内存缓存显示为持久保存。
- 上传到选定分支时生成完整快照，包括来源已删除的文件；覆盖目标文件状态并保留目标提交历史。并发更新时会重新读取目标，最多接续最新提交重试三次；不使用强推。首次上传和重试都验证目标提交及分支。
- 单次上传可选择保留或清理源码；批量上传开始时也会询问。只有远程验证成功、同步凭据和快照记录已持久保存后，才清理所选版本的源码。文件清单和远程提交链接继续保留。
- 上传成功会绑定目标仓库 ID、固定名称、分支和清理选择。再次上传及批量上传沿用绑定，不随源项目名称重新建仓；只有点击“修改项目名称”才重命名现有仓库，并更新历史链接。另存副本不会改变原绑定。之后“一键更新”会下载新版本、归档旧版本，再同步到该目标；上传失败时保留新文件，可重新上传或再次点击更新重试。尚未配置目标时先下载，使用上传入口选择目标。
- 查看和上传历史版本使用该版本的源码；清理后的文件优先从保存的目标提交读取，不依赖源仓库的当前 HEAD。
- 版本归档可分页获取目标分支的 GitHub 提交，查看、下载、对比和恢复指定版本。恢复以当前目标为父提交生成新提交，旧历史和当前源文件缓存继续保留。
- “当前分支独立副本”保存本地所选提交的准确文件，加入我的项目并记住原始来源；后续更新写入固定目标分支。它是独立仓库，GitHub 原生 Fork 不支持任意非默认分支单独分叉。
- “完整分叉”对原始仓库创建包含全部分支和可达历史的原生 Fork，验证来源及分支齐全后加入我的项目。已有匹配 Fork 可直接关联；同名无关仓库会停止处理。创建超时可稍后重试关联。
- 完整分叉的更新会逐个同步上游分支的完整文件状态，包含删除操作，接续目标提交保留本地历史；新增上游分支自动创建，目标独有分支保留。逐分支显示成功或失败，不把部分完成当作全部成功。

完整分叉保留 GitHub 上的 Git 历史；浏览器中的本地快照不是完整 Git 克隆：保存的是指定提交的文件和本应用同步过的版本，不复制源仓库全部历史。包含子模块或 Git LFS 对象的项目当前会明确提示未能完整获取，不会错误标记为完整下载。

GitHub Pages 使用浏览器直连 GitHub；关闭页面后不会持续执行定时检测。清理浏览器缓存不会删除用户已导出的 ZIP 或文件夹。系统记录备份不包含源码缓存或 GitHub Token；恢复到其他设备后需重新填写凭证并获取源码。

## 批量链接与工作台分支

- 新建链接弹窗切换到“批量导入链接”，严格一行一个项目，支持“备注名  链接”或仅填写链接。备注可以含空格、数字和标点；仅链接时备注保存为空，不自动填写“未备注项目”。支持完整地址、`.git` 地址和 `owner/repo` 简写。
- 批量导入按仓库实际默认分支拉取（例如 `main`、`master`），忽略链接附带的分支。重复链接或已导入的默认分支会跳过；单条失败继续下一条，支持仅重试失败链接、取消后保留已完成项目。私有仓库和限流场景可填写共用 Token 或使用全局 Token。
- 导入后在工作台点击“编辑备注与描述”修改资料；这些编辑不重新下载项目。
- 工作台支持获取分支列表，或直接填写分支名后“切换并重新拉取”。新分支完成校验并持久保存后才切换；失败时保留原分支。原有文件、历史快照、仓库名称及各分支绑定均保留，含 `/` 的分支名也可使用。
- 首次私人仓上传及当前分支副本按来源分支名上传；切换到其他分支后，继续使用同一个已绑定仓库，写入对应的同名分支（缺失时创建）。旧记录里明确指定过的目标分支保持原绑定，切回时恢复；已绑定给另一来源分支的目标不会被覆盖。
- 单次上传、批量上传、一键更新和历史恢复均按来源分支路由。历史记录标明所属分支，跨分支恢复只更新历史版本对应的目标分支。重命名会更新所有分支绑定；导出设置备份会排除各分支 Token。

## 批量分叉、更新与响应式布局

- 项目库勾选项目后可执行“批量分叉”“批量更新”“批量分叉同步”。“仅选有更新”会选中当前筛选范围内已检测到变动的项目。
- 批量分叉可选完整来源仓库（全部分支和历史）或当前分支独立私人副本，支持逐项改目标名称；验证成功后加入我的项目。同一来源的完整 Fork 只创建一次，其余来源分支关联已有目标；避免本批不同项目使用同一目标名称。
- 更新与同步使用原有来源和目标绑定，按对应分支追加提交，保留历史。完整 Fork 同一目标的多条管理记录共享传输结果，但各自刷新本地快照。部分分支失败会明确显示失败详情，不显示为全部成功。
- 批量任务固定队列、逐项显示结果，单项失败继续下一项；可取消剩余任务、仅重试失败或取消项。已成功项目不重复执行，已下载文件与验证后的远程记录继续保留。
- 工作台按钮使用可换行的紧凑网格，批量主要操作集中展示，标签、精简和删除收进“更多管理”。长名称、备注、描述和标签会在容器内折行；文件路径在列表内省略，代码在自己的区域滚动，弹窗限制在视口内滚动。保留原背景及配色。
- `npm run test:layout` 在生产构建后使用 Chrome 检查 320、375、480、640、768、1024、1440 像素宽度下的主页、项目库、工作台、历史、日志和各弹窗（合计 140 种状态），包括长内容与按钮重叠检测。需要已安装 Chrome，或通过 `CHROME_BIN` 指定可执行文件；CI 在部署前自动执行。检查只使用隔离的合成数据，不向 GitHub 执行上传、分叉等写操作。

## AI 日志与可选服务端

`npm run dev` 使用本地 Node 服务，AI 功能需要服务端 `GEMINI_API_KEY`（可通过 `GEMINI_MODEL` 指定模型）。纯静态 Pages 未配置 AI 服务时，原日志入口提供明确标注的本地提交摘要。

部署独立 AI 后端时，在构建环境设置 `VITE_API_BASE_URL` 为其地址，并由该后端配置正确的来源访问策略。生产同源 Node 部署可在构建时设置 `VITE_API_MODE=server`；运行时使用 `NODE_ENV=production npm start`。GitHub 或 AI 凭证均不应写入静态构建环境的 `VITE_*` 变量。

## 部署

GitHub Actions 使用 `package-lock.json` 和 `npm ci`；PR 自动检查类型、测试和 Pages 构建，main 更新后部署。Pages 构建路径为 `/Get-Up_GitVault/`。

浏览器、Electron 和 APK 的现有导出入口继续保留。桌面/手机打包应使用适合本地资源的 Vite base（通常为 `./`）；实际写入系统目录仍需要相应原生桥接能力。
