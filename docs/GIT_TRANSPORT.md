# 源码传输与限流恢复

网页版默认无需服务：REST 上传将小型 UTF-8 源文件合并到单次 Git Trees 请求，按最多 2 MiB JSON 文本分批，每个文件最多 512 KiB；较大文本项目继续分批合并，已校验批次可复用；二进制、大文本和断点文件仍使用已校验的 blob。文件树在本地计算 Git SHA，远程树不一致时停止提交。未改文件继续复用已有对象。不能承诺 GitHub 永不限流。

明确的 403/429 限流响应会暂停并显示倒计时，前台任务持续等待后重试，用户可取消，不再两次重试后直接结束。等待时间遵守 Retry-After / 主额度重置时间，重复拒绝逐步延长间隔；无明确限流原因的权限失败、网络丢失的写响应和 5xx 不盲目重放。刷新后保留冷却期限、下载片段和上传 blob 回执，批量任务通过已有恢复入口续办，并重新核对固定仓库与分支。浏览器关闭或被系统杀死后不能保证后台继续。

下载文件按最多 32 个或约 4 MiB 一批写入 IndexedDB；中断时已保存的批次保留。缺失文件超过 12 个时优先尝试固定提交的 ZIP，不再以项目合计 32 MiB 阻止整包尝试。HTTP 响应直接流式交给解压器，每次最多喂入 8 KiB 压缩数据，等待已完成文件的哈希和保存后再继续读取。传输层不调用整包 arrayBuffer，保留读取队列槽位、取消及 60 秒无活动超时；收到数据或完成保存时重置空闲期限。ZIP 文件按可信清单限定解压大小、校验 SHA；路径异常、重复文件或缺失会停止该整包，保留已验证片段，回退补齐。跨域、代理或 GitHub 压缩包仍可能不可用，不保证每个环境均能整包下载。逐文件回退按 blob SHA 去重，同一内容多个路径只下载一次，支持不同路径复用已缓存正文。全部成功后才发布新快照；清理进度只读取索引键，不重新载入全部文件内容。浏览器仍需容纳单文件字节和返回的项目正文，受 WebView/浏览器内存及 IndexedDB 配额约束，流式 ZIP 不代表任意大小项目都可处理。

## APK 原生 Git（无需服务）

新版 APK 注册 GitVaultGit 插件，默认使用 JGit 直接通过 HTTPS 连接 github.com。已有配置可在“源码传输方式”切换到“APK 原生 Git”。Token 仅在本次内存凭据提供器使用，不保存进 Git 远端或配置。源码使用应用私有临时裸仓库，结束、失败或取消后清理；不检出或执行源代码。

拉取固定提交，推送以目标分支最新提交为父版本保存完整文件快照，保留删除、模式和历史；普通推送，不强推。目标 ID 在传输前、推送前核对，客户端再次核对提交树与目标分支。原生 Git 不走逐文件 REST blob 写入队列；仓库管理、分叉、跨设备记录仍使用 REST 并可能限流。取消整个项目合计 100 MiB 的限制。授权主存储目录后，Git 对象先落盘，正文从原生 Git 直接流式写入目录，上传从目录流式读取；桥接只传清单和文件引用。未选目录时，文件通过最多 384 KiB 原始字节的分块传过桥接（Base64 请求体约 512 KiB），下载逐文件校验并保存进度；上传逐文件校验、分块落盘后核对完整清单，再创建提交和推送，不一次把整个项目序列化进原生桥。开始前检查临时磁盘空间，空间不足时明确停止；仍受设备存储、WebView 内存、浏览器缓存配额和 GitHub 自身规则约束，不保证任意大小项目均可处理。不支持完整 LFS/子模块，不保留长期 Git 对象缓存。Git 计算和网络在原生工作线程执行。目录上传每批最多 256 个文件引用，原生层连续读取、校验并暂存；批次共享 Git 对象写入器，目录列表在本次任务内复用，避免每个文件反复从授权根目录查找。任务结束即释放目录索引。Git 拉取写入目录也复用目录列表，恢复时不重复哈希已经通过 begin 校验的片段，但发布前仍对实际目录做完整验证；取消会中断最终验证。原生逐文件进度最多约每 200 毫秒汇报，批次完成后汇报总体进度。

## 可选自有 Git 服务

仓库创建、原生 Fork、重命名、Token 校验、跨设备账号记录仍使用 GitHub REST API。源码拉取和推送可在设置 → GitHub 凭证与连接 → 源码传输方式切换到 **Git 推送／拉取（使用自有服务）**。网页版默认使用带限速的 REST 模式，切换不改变项目 ID、固定目标、标签、备注或分支映射。

## GitHub Pages 与 APK

GitHub Pages 只承载静态页面，不能启动服务器上的 Git 命令。仓库包含可单独部署的 Node/Git 服务，网页和 APK 都可以连接这个服务。它不是浏览器直连 GitHub 的 Git 协议，也不是 APK 内置原生 Git。

填写你自己部署或信任的 HTTPS 服务根地址，例如 `https://git.example.com`；“检查 Git 服务”访问 `/api/git/health`，不发送 Token。保存 Git 模式后，源码操作会把本次所需的 GitHub Token 和文件发送给该服务。服务不设置 Token 到远端 URL、磁盘配置或日志；只在 Git 子进程环境中短暂使用。传输失败不会自动改用 REST 再推送，避免重复或不明确的写入。

源码通过 `git fetch` 获取对象，通过 `git push` 发送 Git pack。服务每次创建独立临时裸仓库，完成、失败或取消后删除；不保留服务端长期源码副本或增量对象缓存。用户选择是否销毁本地源码，仍只作用于浏览器／APK 原有缓存，已有远端历史和快照保留。

## 部署服务

需要 Node.js 22+ 和可运行的 Git CLI（建议 Git 2.39+）。Git 不需要预先配置用户账号、凭据助手或 SSH Key。

```bash
npm ci
npm run build
GITVAULT_GIT_ENABLED=1 \
GITVAULT_ALLOWED_ORIGINS=https://tingtingftt.github.io,https://localhost \
NODE_ENV=production npm start
```

服务默认端口 3000。用自己的 HTTPS 反向代理转发到这个端口；代理需允许较大的 JSON 请求，并将传输超时设为至少十分钟。`GITVAULT_ALLOWED_ORIGINS` 填完整来源，多个以逗号分隔：GitHub Pages 来源是 `https://tingtingftt.github.io`（不带项目路径），Android APK 来源是 `https://localhost`。同源页面默认可用，其他来源需要明确配置。无需开放通用 URL 代理。

也可使用随附镜像配置：

```bash
docker build -f Dockerfile.git -t gitvault-git .
docker run --rm -p 3000:3000 \
  -e GITVAULT_GIT_ENABLED=1 \
  -e GITVAULT_ALLOWED_ORIGINS=https://tingtingftt.github.io,https://localhost \
  gitvault-git
```

镜像和仓库都不包含用户 Token。服务默认不启用；只有设置 `GITVAULT_GIT_ENABLED=1` 才开放传输。服务每次先向 GitHub 验证仓库访问权和固定仓库 ID，推送前再次确认身份。源码模式不需要给服务提供 GitHub App、组织管理或其他额外权限。

在设置中填服务根地址，选择 Git 模式，检查连接后保存。部署网页和 APK 不会自动创建、发布或购买这个服务。未配置时，线上页面继续使用 REST；`VITE_GIT_SERVICE_URL` 只用于构建时预填服务地址，不自动启用或发送凭证。

## 分支和历史

- 读取目标分支时，404、明确的 `422 No commit found for SHA` 或空仓库 409，都先重新确认仓库 ID 和真实分支列表。只有列表确认没有该分支时才允许后续创建；权限错误、其他 422 或已列出的分支不能被当作空分支。
- 推送使用已固定的目标分支。目标分支不存在时创建该分支；已有分支时，读取最新目标提交，以它为父提交保存完整文件快照，包含来源中的删除操作。
- 使用普通 `git push`，不强推、不删除其他分支。明确允许冲突接续的任务最多重新读取并接续三次；并发产生的提交仍保留在历史中。
- 推送回执还要通过 GitHub API 核对目标分支、提交树、文件 SHA 和模式；校验完成后才保存上传回执或清理本地源码。同一快照重试会复用已有目标提交。
- 拉取固定到完整提交 SHA，检查文件清单和每个 blob 的字节哈希。二进制、可执行文件和符号链接内容保留；服务不会在工作目录展开或执行这些文件。子模块、LFS 实体内容仍不在完整下载支持范围，遇到时明确停止。

当前服务按单次源码总大小 100 MiB、请求体 150 MiB、同时两个传输和十分钟任务超时限制资源。取消浏览器请求会中断服务上的 Git 进程并清理临时目录；已经到达 GitHub 的提交不能回滚，重试时重新验证目标。

## 验证

`npm test` 包含真实本地裸 Git 仓库测试：新分支、连续历史、删除文件、空仓库、Unicode／二进制／可执行模式／符号链接、并发接续、拒绝强推、取消与临时目录清理。HTTP 集成测试验证跨域来源、健康检查不带 Token、固定 ID、错误不降级、前端清单校验及取消传递。测试不向外部 GitHub 仓库推送。

Android 模拟器还验证超过 100 MiB 的分块落盘、逐文件哈希读取、损坏／未完成分块拒绝，以及真实 WebView → Capacitor → 原生文件暂存／释放。大项目仍需足够的本地空间；临时预检保留约三倍源码大小及 64 MiB 余量，以容纳 Git 对象、下载进度和持久缓存。可选自有服务仍使用上文独立的服务端资源限制，不随 APK 的分块协议改变。

目录主存储使用 SAF 持久授权及私有索引，更新先核验候选快照后切换，旧正文按引用清理。迁移／清理规则见 [Android 说明](ANDROID.md#缓存目录与下载)。新增原生文件测试覆盖超过 100 MiB 单文件写入、从目录直接生成 Git 对象、损坏检查点恢复、实际改动识别及安全清理边界。

## 传输耗时与首次上传优化

操作日志新增“拉取传输明细／上传传输明细”，记录识别、准备、传输、最终验证等阶段和总耗时。网络阶段包含 API 排队与限流等待，不将等待误称为有效传输速度；APK 另外返回批量暂存、Git 获取、目录写入验证和 Git 推送细项，这些已包含在总耗时内。日志不保存凭证或文件正文；原有操作结果日志继续记录失败原因和账号回执状态。内容与固定目标分支完全一致的 REST 上传，核对目标分支未变化后直接跳过，不再创建文件树或重复提交。

首次网络耗时仍受仓库内容、压缩率、设备磁盘和 GitHub 链路影响。网页大量二进制的首次上传仍使用 REST blob；需要 Git pack 时可选择上文自有服务，服务当前资源限制保持不变。本次未引入长期原生 Git 对象缓存，上传后销毁与手动清理的范围保持一致。
