# 传输性能验证

## 可复现的网页方案对照

运行 `npm run benchmark:transfer -- report.json`。固定种子 77，64 个文件、4 MiB 正文，一半随机二进制、一半可压缩数据；本地 HTTP 每个响应等待 15 ms，最多三个读取工作者，不包含 GitHub 限流和真实公网。三种策略均核对所有文件 SHA 与最终 Git 树，失败会退出非零。

2026-10-18 本地 Linux / Node 22 的一次观察：

数值顺序：逐文件基线 / 上一版 ZIP 方案 / 本次方案。

| 场景 | 请求数 | 响应字节 | 耗时 ms |
| --- | --- | --- | --- |
| 首次 | 64 / 1 / 1 | 5,593,472 / 2,107,217 / 2,107,217 | 446.65 / 70.56 / 41.75 |
| 无变化 | 0 / 0 / 0 | 0 / 0 / 0 | 2.24 / 1.44 / 2.89 |
| 更新 4 个文件 | 4 / 4 / 4 | 349,592 / 349,592 / 349,592 | 38.85 / 36.75 / 39.58 |
| 更新 16 个文件 | 16 / 1 / 1 | 1,398,368 / 2,107,220 / 2,107,220 | 118.21 / 30.89 / 28.16 |

这里的比较用于验证首次整包减少请求、小更新只补变化文件，以及保持较小项目原有 ZIP 路径；没有证据表明本次对首次 ZIP 下载有额外固定倍数的提速，不代表真实用户能获得相同速度倍数。零网络场景的毫秒差异主要是本地计算噪声。大于 32 MiB 的项目新增占比判断：若缺失正文不足四分之一则直接补拉，此分支由计划单元测试覆盖，避免为少量小文件重下庞大未变化内容。

CI 使用 Node 22 重新运行并上传原始 JSON，数值会随机器变化。

## APK 原生对照

Android 自动化测试在同一模拟器上暂存 128 个随机文件、8 MiB 正文，再启用保留对象重复暂存。硬性检查：两次读取当前源码均为 8 MiB；首次新写 128 对象，后续新写 0、复用 128；最终树一致；篡改源码仍拒绝；取消仍中断。另用公开仓库固定提交检查冷／热浅获取及内部引用切换，不能使用缓存绕过固定版本。

测试日志中 `GITVAULT_BENCHMARK` 和 `GITVAULT_FETCH_BENCHMARK` 给出实际耗时。测试不向用户仓库推送。仓库既有 float 完整 2,952 文件测试继续执行。模拟器和模型测试不替代具体手机 SAF 提供者与公网环境验收。

## 实机验收

在同一手机、同一授权目录、同一网络、同一固定提交分别测试首次拉取、首次上传、完全不变更新、小范围更新、取消恢复和上传后清理。记录操作日志中的总耗时、原生阶段、缓存命中、新写／复用对象、网页 API 排队／限流等待；不要把累计响应处理耗时误认为纯网络速度。

双设备验收继续覆盖：A 上传／分叉，B 同账号重新导入、比较并恢复固定仓库、修改标签，更新仅写映射分支；再测试改名、同名不同源码、删除重建、账号记录待补写和取消后重试。此项需要两个真实设备和账户授权，不能把自动化模拟当成已在用户设备上完成。

## 五场景生产客户端对照

同一命令现增加 `client.results`：直接运行 `githubClient` 与真实 IndexedDB 缓存代码，在本地 HTTP 服务上完成固定版本拉取、创建提交、非强制更新分支、验证、失败和重试。数据仍为 64 文件 / 4 MiB，包含重复内容；上传使用实际 UTF-8／二进制识别，重复 SHA 复用。每个响应等待 15 ms；为观察请求开销，测试关闭请求间隔和写入间隔，**不代表 GitHub 的实际上传耗时**，正式版的限流排队保持开启。

| 首次拉取 | 4 | 0 | 0 / 0 | 204.19 |
| 无变化拉取 | 3 | 0 | 0 / 0 | 60.11 |
| 首次上传 | 40 | 36 | 32 / 0 | 928.83 |

硬性验证：首次上传树与来源相同；无变化上传零写请求且不新增提交；小更新只处理变化正文，提交接续旧历史；上传中断未移动目标分支，重试先验证 8 个已确认对象而不再次上传；不完整 ZIP 的已验证正文和重复路径复用持久保留，重试只读取余下 8 种 blob，不再请求 ZIP；所有场景保持 main 分支和旧快照不变。时间不作为通过门槛。

APK 增加 `NativeSyncBenchmarkTest`：128 文件 / 8 MiB 的磁盘源文件，使用生产 `GitSnapshotStore` 与可选对象缓存，实际向本地裸仓库执行 JGit push，记录首次上传、无变化、小更新、取消和恢复的阶段时间、源字节、新写与复用对象。首次应写 128 对象；无变化写 0；4 文件更新写 4；取消前处理 64 文件并保持远端不动；恢复读取当前全部 128 文件验证，但复用此前对象、不再重复压缩写入。每次验证目标树、历史父提交、main 分支及最后清理。本地 Git 不包含公网或 GitHub 身份 API 耗时。首次原生拉取的公开固定提交冷／热数据由 `GitObjectCacheTest` 单独记录。

已完成构建 1.0.32 的同模拟器观察：8 MiB 原生暂存首次 4105 ms、缓存复用 780 ms，新写对象 128 → 0；固定公开提交浅获取 1734 ms → 578 ms。完整读取当前源字节、最终目录校验仍保留，不能用缓存跳过内容验证。批量桥接和目录索引沿用现有实现。

## 恢复与失败分类

操作日志的传输明细区分网络／超时、GitHub 限流、ZIP 解压、清单或 SHA 校验、空间／配额、授权和其他存储错误。原异常、HTTP 状态和限流恢复时间不被改写；成功补拉也保留 ZIP 失败分类。只有网络 I/O 边界标记网络错误，应用内部 TypeError 不冒充网络失败。

网页已验证的部分 ZIP 内容按固定提交保存恢复决定，刷新／重开后仅补缺失 blob；换提交重新规划。恢复决定有效期 7 天，与下载进度一起在成功保存快照或清理临时缓存时移除。空间不足和目录授权错误立即停止，不继续发起备用 ZIP 或 blob 请求；取消保留已落盘批次。

## 跨设备与异常验收边界

自动化 HTTP 流程已覆盖 A 上传／完整 Fork → 清空本设备记录模拟 B → 同账号重新导入 → 比较与固定目标 → 标签跨会话恢复 → 更新仅写映射分支，以及同名代码不同、改名、另存切换、账号记录补写失败和取消重试。新增：A 的改名主仓库被删除或同名重建后，B 仍能从原来源拉取参考，保留旧固定 ID 与异常标记，不读取或覆盖同名新仓库，不伪造同步回执。用户须经已有目标管理流程明确处理旧关系。

这些是隔离客户端会话和模拟器验收，**两个真实手机、具体 SAF 目录提供者、真实公网和账号权限仍需实机验收**。不能将其标记为已在用户设备全部完成。

## 空间与销毁边界

可选原生对象缓存默认关闭；空闲缓存合计上限 512 MiB，7 天后于后续任务回收。上限不包含活动 Git 任务、主目录或独立导出；传输仍检查设备可用存储并保留余量。关闭缓存、项目源码清理、上传后销毁和清理临时缓存都会清除所有共享 Git 加速对象，防止从来源或上传历史对象重建已清理源码。活动任务期间禁止清理。

项目清理删除其下载正文、所属缓存与恢复进度，保留必要快照元数据、固定关系和 GitHub 历史；其他项目仍引用的正文、其他项目主目录和独立导出按原规则保留。“彻底销毁”是删除应用管理范围内可还原该项目的缓存副本，不是远端删库，也不保证闪存物理擦除；用户自行导出的文件由用户管理。删除或授权失败要明确报告，不能显示成功。

## 本轮增量、重复工作与取消修正

以 `9dd7041611a2499099140f15b09f886ae4b7a125` 为修改前基线，同一 Linux / Node 24、种子 77、64 文件 / 4 MiB、本地 HTTP 每响应 15 ms，依次运行旧实现和新实现。两边使用相同的新基准脚本；不向外部仓库写入。新增 `hashCalls`（所有 SHA 计算调用，含树和验证）和 `bodyWrites`（IndexedDB 正文 put 次数），以及同一任务内的“拉取 → 保存 → 内容不变上传”链路。

| 场景 | HTTP 旧 / 新 | 哈希调用旧 / 新 | 正文写入旧 / 新 | 耗时旧 / 新 ms |
| --- | ---: | ---: | ---: | ---: |
| 首次拉取 | 4 / 4 | 64 / 64 | 0 / 0 | 240.12 / 265.81 |
| 首次上传 | 40 / 40 | 136 / 136 | 0 / 0 | 1075.68 / 1143.28 |
| 无变化上传 | 5 / 5 | 64 / 64 | 0 / 0 | 326.98 / 417.81 |
| 拉取、保存、无变化上传 | 8 / 8 | 128 / 0 | 64 / 0 | 602.19 / 192.32 |
| 4 文件更新拉取 | 7 / 7 | 4 / 4 | 0 / 0 | 132.22 / 141.75 |
| 4 文件更新上传 | 14 / 14 | 70 / 70 | 0 / 0 | 508.60 / 561.20 |
| 上传中断后恢复 | 41 / 41 | 132 / 132 | 0 / 0 | 1061.81 / 1170.80 |
| 下载中断后恢复 | 11 / 11 | 8 / 59 | 0 / 0 | 208.57 / 405.07 |

这是一次观察，不是普遍速度倍数。主要可证明的减少是同一份已验证内存内容不再在保存、上传时反复哈希，已有正文不再为每个快照重写。首次网络请求数并未因此减少；单独构造的上传文件仍须首次校验。恢复下载的 51 个持久检查点重新进入内存后也须验证，故新实现本阶段为 51 + 8 次，后续保存可复用结果；旧实现把这部分检查留到保存阶段。不能仅比较一个阶段就称整体变慢或变快。表格不包含后续取消调度让步间隔等微调，CI 每次保存当前代码的原始报告。

实现边界：

- 文件差异计划按固定清单比较新增、修改、删除及模式变化。已有内容可复用时，网页更新选择变化正文，不为减少请求而重新下载包含未变化资源的 ZIP；全部内容缺失时仍可整包获取。
- 仅复用同一任务内的账号身份及完整 SHA 指向的不可变提交、树。Token、任务信号隔离；分支头、仓库身份、账号记录头不缓存。更新检查得到的提交可供随后固定 SHA 拉取复用。
- 已确认、未发生身份或分支映射变化的账号绑定更新不重新走导入代码比较；首次导入、改名、另存、异常目标及新分支仍走原核验流程，写入前身份及分支验证保留。
- 完整 Fork 同步先比较对应分支的源／目标树；相同则再次确认目标身份和分支头，跳过正文下载和代码提交。有变化才按固定来源提交执行现有历史接续流程。
- APK 更新先读旧快照引用，原生准备阶段只扫描选中的当前目录，不遍历历史目录。复用文件在原生层连续读取并写入，沿用现有目录索引，不再每个未变化文件跨桥接调用。内容完全相同的新提交可共用一个已验证目录，多提交引用独立清理；旧版单引用格式兼容。
- APK **有文件变化的新版本仍保留独立、完整的可见目录**，所以仍需要复制未变化正文及最终完整校验；本轮没有把它改为原地覆盖或只含差异的目录。共享目录上传也仍读取当前实际文件，不能使用大小、mtime 或旧对象代替内容核验。未来若消除此类复制，须另做可恢复的工作目录事务及历史正文管理，不能牺牲旧快照与取消恢复。
- 缓存继续默认关闭，空闲对象池总上限 512 MiB、7 天回收，活动任务及项目目录不计入该加速池上限。清理与彻底销毁规则沿用，未增加隐蔽的永久源码副本。

取消：HTTP 队列和限流等待沿用可中断策略；目录扫描、哈希、复制、最终校验、导出和 ZIP 接入独立原生任务标识，取消直接设置停止标记，不排到正在阻塞的文件 I/O 队列之后。循环在文件／数据块边界检查；系统提供者的单次阻塞调用可能要等返回。原生 Git 和目录调用均等到工作停止及清理确认后才释放 UI 锁，期间显示“正在取消”。取消还会撤销本任务待确认弹窗，不影响无关弹窗。已成功提交不会回滚，未知写入结果留待重新核实；已完成项目和有效下载检查点保留。

新增回归覆盖：内容变动使内存验证失效、已有正文零重写、取消保留旧快照、目录和 Git 取消确认、活动行阶段进度、Token／任务隔离、不可变读取复用、无变化完整 Fork 零正文传输及同名目标重建保护。Android 覆盖原生复用新增／修改／删除、相同内容多提交独立清理、历史目录修改不触发当前更新扫描、扫描取消不发布候选。真实用户手机 SAF 提供者、两台实体设备和公网吞吐仍须实机验收。

APK 小增量补拉：若当前版本或恢复候选已有可复用文件，剩余不超过 32 个、合计不超过 16 MiB 且大小均明确，则通过现有共享 GitHub 请求队列按固定 blob SHA 补拉，直接保存到原生目录；不为这些小变更重新获取一个冷 Git pack。仍核验每个 blob 与最终目录，沿用限流等待／取消。首次、全部缺失或较大变化继续原生 Git 流式获取，保留对象缓存可改善后续对象协商。此阈值是传输策略，不是项目总大小上限。

## 超时与断流恢复验证

在相同本地 HTTP 基准中新增 `automatic-upload-recovery`：第九个二进制对象写入前模拟断开一次，客户端先按 SHA 查远端，确认缺失，再在同一任务中继续。64 文件 / 4 MiB 的一次观察：44 次 HTTP、38 次写请求、34 个二进制对象成功写入、1 次缺失对象查询，约 2121 ms（包含固定 1 秒恢复等待）。本次没有重新上传此前成功的对象，目标仅生成一个发布提交，其他分支保持不变。首次上传仍是 40 次 HTTP、36 次写请求；无变化上传仍为 5 次 HTTP、零写；4 文件小更新仍仅写 4 个 blob。这说明恢复容错增加，没有证据把它说成公网带宽提高。

持久中断场景现模拟连续失败，超过两次自动恢复后才结束，确认 8 个已上传对象和旧快照保留，再重新进入恢复。模拟服务按目标仓库隔离对象可访问性，避免误把其他仓库已有的同 SHA 对象视为本目标已接收。

新增网络回归覆盖：安全读取的超时、截断响应、网关错误、恢复等待取消；活动正文持续读取不触发总时限；流式解压／保存消费者开始后不在网络层重放；丢失成功 blob／树／分支响应后无重复写入；确认未写入才重传；同名仓库重建拒绝；原生推送响应丢失和连接提前结束分别核对目标头、复用原提交与历史；未知远端结果不重推。原生 HTTP 工厂按任务管理连接，测试取消会触发断开，不改变其他任务及全局工厂，真实公网 HTTPS 获取继续在 Android 测试覆盖。

这不是断网无限重试，也不是从中断 pack 的某个字节位置接续。APK 仅复用已完整写入的有效对象；临时会话结束按原缓存选项清理。每次开始上传仍核验当前源码，最终分支／树与账号回执核对继续保留。
